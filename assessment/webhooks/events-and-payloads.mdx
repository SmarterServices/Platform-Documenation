# Events & Payloads

## Supported Events

Our webhooks implementation allows for a basic set of assessment-based events that you can capture. We are open to adding more event types as they are required by our customers. If you have a need for a new event type, please contact [developers@smartermeasure.com](mailto:developers@smartermeasure.com) with your request.

| Event | Fired when... |
|-------|---------------|
| `assessment.created` | An assessment is created. |
| `assessment.section-start` | A section is started. This request will include the section that is being started. **Note:** This can be fired multiple times if the user leaves and returns to the assessment without submitting the answers. |
| `assessment.section-complete` | A section is completed. This request will include the scoring details for the section completed. |
| `assessment.completed` | The assessment is 100% complete. |
| `assessment.stopped` | The user has chosen to stop taking the assessment for the current period. |

## Event Formats

When event data is sent back in the HTTP POST, it can be sent as either JSON or XML. This setting can be configured for each event type. The sample event data below includes both formats.

## Event Data Structure

When an event occurs that you have turned on, we will send an HTTP POST request to the URL specified for the given event. If we receive an HTTP Response code of 200, we deem the request as being successful; anything else will be considered a failure.

If the request is considered a failure, the URL is unavailable, or the request takes too long to respond (more than 10 seconds), we'll cancel the request and try again later. Retries will be sent for the next 48 hours at 15 minute intervals — effectively 192 attempts.

<Warning>
It cannot be assumed that webhook callbacks are sent in the proper order. Your application should check the request timestamp and act appropriately.
</Warning>

Each event will contain a `callback_id` to help you track the actual ID of the callback in our system and an `event` field that will allow you to track the type of event that was fired.

  "callback_id": "6cec1a2a710b431f9c8a51cdc55854c2",
  "callback_event": "assessment.created",
  "user": {
    "user_id": "8152142",
    "internal_id": "",
    "first_name": "Demo",
    "last_name": "User",
    "email": "demouser@smartermeasure.com",
    "assessment_pin": "j8rScGZR",
    "date_created": "2013-06-12T03:30:00Z",

  },

    "version": "3",

    "user_results": "/users/8152142/results"

## Section Code Mappings

Each section-specific payload will include a `code` key to let the target application know which section was started or completed.

| Section Code | Assessment Section |
|--------------|-------------------|
| `PersonalAttributes` | Individual Attributes |
| `LearnStyles` | Learning Styles |
| `LifeFactors` | Life Factors |
| `Math` | Math |
| `PersonalInfo` | Personal Information |
| `personalRating` | Personal Rating |
| `Reading` | Reading Rate & Recall |
| `student-svc-interest` | Student Services Interest |
| `TechComp` | Technical Competency |
| `TechKnowledge` | Technical Knowledge |
| `Typing` | Typing Speed & Accuracy |
| `writing` | Writing |
